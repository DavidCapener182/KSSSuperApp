# PRODUCT-05 commercial workspace design map

**Basis:** PRODUCT-05 frozen Candidate 1 review in `/private/tmp/kss-product-05-crm`; UI01 competitive research and journey audit in the shared checkout (untracked at the integrated branch); current integrated Candidate 2 code at `e9963af`. This map is for the new bounded Office/Super synthetic Development pass. It does not authorise deployment or real business data.

| Researched pattern | User job | KSS equivalent and current gap | Proposed KSS implementation |
| --- | --- | --- | --- |
| [HubSpot Sales Workspace activity summary](https://knowledge.hubspot.com/sales-workspace/manage-sales-activities-in-the-updated-sales-workspace) | Start with due work and recent activity | CRM overview has factual counters but few source-linked work records | Show actual due/overdue follow-ups and decisions, with exact Opportunity links; count inventory moves below work |
| [HubSpot pipelines and board](https://knowledge.hubspot.com/object-settings/set-up-and-customize-pipelines) | Scan stages and advance a deal | KSS has five active stages and guarded transition; cards understate next action | Preserve board; rank current action and deadline above the stage-control; keep Closed distinct |
| [Pipedrive pipeline priority](https://support.pipedrive.com/en/article/how-are-deals-ordered-in-the-pipeline-view) | Find overdue and unplanned deals quickly | KSS already records Task due/next action but presents it weakly | Surface factual overdue/today/no-future-action labels and sort with explicit server facts where available |
| [Pipedrive deal/account detail](https://support.pipedrive.com/en/article/detail-view) | See relationship, contacts, stage and work in one place | KSS Organisation and Opportunity detail have those sources but long forms dominate | Reorder identity, next action, contacts, pipeline stage and history into account/deal workspaces |
| [HubSpot record associations](https://knowledge.hubspot.com/records/work-with-records) | Navigate from account/deal to related records | KSS source links exist; exact commercial-to-delivery context spans modules | Add Office-only factual handoff projection; keep source authority and permissions |
| [Salesforce activity timeline](https://help.salesforce.com/s/articleView?id=sales.activities_view.htm&language=en_US&type=5) | Inspect attributable upcoming and past work | CRM activities and Tasks are distinct typed records | Show existing timeline; collapse manual entry, label it as a note rather than dispatched communication |
| [ServiceNow staged playbook](https://www.servicenow.com/docs/r/customer-service-management/setting-up-csm-playbooks.html) | Follow action ownership and blockers through a handoff | Mobilisation has templates, actions, dependencies, blockers and explicit human handover | Portfolio shows owner, target, open actions, blockers and next action; detail links to exact sources and continuing Service Delivery |

**Deliberately not adopted:** HubSpot weighted forecasts, Pipedrive scoring, Salesforce generic automation, email sequencing and revenue dashboards. KSS lacks an accepted probability, contract, invoice and communication-dispatch authority for those claims. A CRM Opportunity estimate remains an estimate. A recorded `WON` state never starts Mobilisation, Site Service, Event or Service Delivery automatically.

**Contract decision:** A new narrow read-only Office/Super projection is needed for exact Organisation → Opportunity → Mobilisation → source → Service Delivery facts and a paginated Mobilisation portfolio. It must be tested before any claim of server acceptance. Existing guarded mutation routes remain the only action paths. The UI uses realistic static synthetic scenarios for visual review if disposable source fixtures are unavailable; they are labelled and never mixed with live source responses.
