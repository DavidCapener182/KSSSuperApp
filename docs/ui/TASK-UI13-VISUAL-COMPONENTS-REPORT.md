## Shared proposals for UI11 / later controlled integration

1. A source-labelled summary card should present **identity + context + factual state**, with optional freshness and optional action. It accepts only caller-authorised facts and an exact record/version identity where relevant. It must not derive readiness or widen linked file access. Informational cards need no forced action.
2. A responsive data-list contract should require explicit mobile fields, result count, filter state and full-size row actions. Its desktop and phone representations must use the same authorised dataset.
3. A shared action-feedback contract should distinguish pending request, server acceptance, authoritative readback and refresh failure. This prototype deliberately reports no server acceptance.
4. Tabs, dialog focus return, history actor/time/version and state panels should be reviewed against the real role journeys before shared adoption.
