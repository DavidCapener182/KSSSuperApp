## Implementation

- New guarded `service_delivery_portfolio` RPC and `/api/service-delivery/portfolio` endpoint filter the complete Office/Super-authorised set by Client, Site, Service, owner, state and view-specific date before 25-row pagination. Views are All, My services, Reviews due, Actions overdue, Meetings upcoming and Changes awaiting application. Factual cards show review/action/blocker/meeting/change counts, owner and later source drift. Date meaning is stated per view. No service-health or SLA score is derived. Existing Service Delivery start and source authority remain unchanged.
- `Review workspace` composes one existing review period's 21C current staffing/attendance cards with its scheduled/held meetings and open period or overall-service actions/blockers. 21C still makes a fresh exact-period read with as-of/source labels. The workspace records no review outcome or frozen performance fact.
- An authorised `SERVICE_CHANGE_RECORDER` may request a narrow candidate read for one approved, unapplied 21D Site Service change. It returns only a current event ID/type/revision/date that meets the existing 21D application guards. The manager must still perform the Site Service action in that module, explicitly record the exact candidate with a reason, and pass the existing command's transaction-time checks. The UI verifies the exact application event through management readback before treating it as confirmed. Management approval never mutates Site Service.
- Commercial Handoff on the base already links an exact continuing Service Delivery record; Service Delivery detail links back to its exact Mobilisation when native handover was used. The Mobilisation detail links into Commercial Handoff and the guarded Service Delivery start. No automatic start or identity merge was added.
