## Delivered

- Extended the existing `attendance_cases` and `attendance_events` tables with exact `site_shift_allocation_id` foreign keys and Event/Site Shift XOR constraints. Staff self Check In/Out requires mapped Person, active `SECURITY_STAFF`, exact Person allocation, `ACCEPTED` status, planned demand and a Service valid for the duty date. A cancelled demand, effective pause period or Service ended for that duty blocks new Staff self actions even when the allocation remains accepted. Lifecycle changes do not cancel or rewrite allocation or attendance.
- Added exact static Site Service/demand manager projection and attributable observed facts, exception, no-show resolution and correction. Manager authority follows the existing active Office/Operations/Super Admin operational role and an exact allocation → demand → Service → Site chain. SiteAssignment, work-role title, allocation ownership or UUID knowledge alone grants none of those actions. This task does not broaden CRM, private People/Profile, SIA, onboarding or finance access.
- Added one Staff My Attendance list with explicit Event/Site Shift source, shared actionable-first bounded pagination, exact typed focus and Load more. Existing Event focus URL and Event RPCs remain. Static focus is `/my-attendance?source=SITE_SHIFT&allocationId=<exact-id>`. My Deployments links accepted static allocations to that focus. The Site Service page links to a bounded manager attendance view.
- Kept 09A factual vocabulary, append-only event history, actor/method/reason and correction references, expected revision, idempotent retries, no-show resolution and cancellation review. Static cancellation after check-in appends one `REVIEW_REQUIRED` fact; earlier facts remain. No duration, break, worked or payable value is inferred.
